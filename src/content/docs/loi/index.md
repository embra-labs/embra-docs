## Cách đọc lỗi

Mỗi lỗi gồm ba phần:

| Phần | Ví dụ | Thấy ở đâu |
|---|---|---|
| Mã lỗi (`reason_code`) | `HEALTHCHECK_FAILED` | Output `--json` của CLI, và nội dung chép bằng **"Sao chép diagnostic ID"** |
| Câu tiếng Việt (`summary_vi`) | "Bản mới không qua readiness trong thời gian khởi động. Bản cũ vẫn phục vụ." | Console và CLI |
| Bước tiếp (`next_action`) | `fix_input` | Dòng dưới câu lỗi trên console, dòng `bước tiếp:` trong CLI |

| `next_action` | Console ghi | CLI ghi | Nghĩa |
|---|---|---|---|
| `fix_input` | "Kiểm tra và sửa thông tin." | `sửa đầu vào rồi chạy lại` | Sửa code, config hoặc input rồi làm lại |
| `rerun_plan` | "Tạo plan mới để kiểm tra lại." | `chạy lại plan` | Plan cũ hết đúng, tạo plan mới |
| `owner_review` | "Cần owner hoặc admin xem và quyết định." | `chủ workspace cần xem và duyệt` | Owner hoặc Admin cần approve hoặc nâng gói |
| `wait` | "Đang xử lý, vui lòng chờ." | `chờ rồi kiểm tra lại` | Chờ một lúc rồi thử lại |
| `contact_operator` | "Cần đội Embra kiểm tra trước khi tiếp tục." | `liên hệ người vận hành` | Đội Embra cần xem. Xem [Khi cần liên hệ](#khi-cần-liên-hệ) |
| `none` | | `không cần làm gì thêm` | Không có lỗi |

Khối **"Nội dung từ app — không do Embra viết"** dưới câu lỗi là chữ lấy từ app hoặc repo của bạn: cuối build log, response app trả cho health check, lỗi Postgres, DNS record Embra đọc được. Nguyên nhân thật thường nằm ở đây.

## Cách tìm mã

- `Ctrl+F` (`Cmd+F` trên Mac) rồi gõ mã lỗi, ví dụ `BUILD_FAILED`.
- Console chỉ hiện câu tiếng Việt? Gõ vài chữ đầu của câu đó: mỗi mục bên dưới có ghi câu bạn hay thấy.
- Mỗi mã có URL riêng: `docs.embra.cloud/loi/#<mã viết thường>`, ví dụ `/loi/#healthcheck_failed`.

## Khi cần liên hệ

Email **hello@embra.cloud**, kèm:

1. **Mã operation** (`operation_id`): dòng `operation:` trong CLI, hoặc nội dung chép bằng **"Sao chép diagnostic ID"** trên console.
2. **Workspace**, project, environment (ví dụ `shop/production`).
3. **Giờ** gặp lỗi, ghi rõ giờ Việt Nam hay UTC.
4. Mã lỗi và câu lỗi, nếu có.

Lỗi cần đội Embra (`contact_operator`) thì console có nút **"Liên hệ hỗ trợ"**, mở email nháp đã điền sẵn mã operation và mã lỗi. Email nháp chỉ có mã, không có secret hay data của bạn.

## Build và deploy

### `BUILD_FAILED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 200 | Không | `fix_input` | `10` | Sửa theo mục này rồi làm lại |

<!-- /reason-meta -->

Không build được image từ code. App đang chạy không bị ảnh hưởng.

Câu bắt đầu bằng `embra.toml:` thì xem [`REPO_CONFIG_INVALID`](#repo_config_invalid). Các câu khác:

| Câu lỗi | Nghĩa |
|---|---|
| `buildctl lỗi: exit …` hoặc `build trong VM không thành công.` | Lệnh build (Dockerfile hoặc Railpack) fail. Nguyên nhân nằm trong build log |
| `railpack prepare lỗi: exit …` | Bước Railpack phân tích repo fail. Lý do nằm trong build log |
| `git fetch lỗi: …`, `git checkout lỗi: …` | Embra không lấy được commit từ GitHub |
| `không thấy Dockerfile.` | `embra.toml` đặt `builder = "dockerfile"` nhưng không có file ở path đó |
| `root không tồn tại.`, `root không phải thư mục.`, `root trỏ ra ngoài repo.` | `root` trong `embra.toml` hoặc **Root directory** sai |
| `Image build ra vượt giới hạn dung lượng của gói.` | Image lớn hơn dung lượng đĩa của gói |
| `… file migration không hợp lệ.`, `migration trùng tên.`, `quá 100 file migration.`, `migration … vượt … byte.` | Thư mục migration có vấn đề. Xem [Viết migration](/huong-dan/database-va-migration/#viết-migration) |
| `preview.seed không tồn tại.` | File khai ở `[preview] seed` không có trong repo |
| `Upload của build này không còn tồn tại. Upload lại rồi build.` | Bản upload từ `embra deploy` đã hết hạn |

**Cách sửa:**

1. Bấm **"Xem build logs"**, đọc từ dưới lên. Dòng lỗi đầu tiên của npm, pip, go, docker thường là nguyên nhân.
2. Chạy lại đúng lệnh build đó trên máy. Repo có `Dockerfile` thì chạy `docker build .` ở thư mục gốc (hoặc ở `root`).
3. Log có `egress từ chối "<host>"`: build cần tải từ host chưa được mở. Gửi tên host tới hello@embra.cloud. Host đang mở: [Embra build app thế nào](/huong-dan/chuan-bi-app/#embra-build-app-thế-nào).
4. Image quá lớn: dùng Dockerfile multi-stage chỉ copy thư mục build (ví dụ `dist/`) vào stage cuối, cài dependency production (`npm ci --omit=dev`), thêm `.dockerignore` bỏ `node_modules`, `.git`, file test.
5. `builder = "dockerfile"` mà không có Dockerfile: bỏ dòng `builder` để Embra tự chọn Railpack, hoặc sửa `dockerfile` đúng path tính từ `root`.
6. Commit và push lại.

<details>
<summary>Dockerfile multi-stage mẫu cho app Node</summary>

```dockerfile
# Ví dụ Dockerfile nhiều stage cho app Node
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
CMD ["node", "dist/main.js"]
```

</details>

**Data an toàn?** Có. Build fail thì không deploy gì, database không bị đụng.

**Retry?** Cùng commit thường ra cùng lỗi. Riêng `không khởi động được VM.`, `VM tắt trước khi sẵn sàng.`, `mất kết nối với embra-buildd giữa chừng build.` là lỗi phía Embra: bấm **"Build lại"** một lần.

**Liên hệ khi:** lỗi phía Embra lặp lại sau khi build lại, hoặc build chạy được trên máy bạn mà fail trên Embra và log không chỉ ra lý do.

Build chạy quá giờ nên bị dừng. Câu lỗi: `build vượt thời gian cho phép.` Thời gian build tối đa theo gói, không quá 25 phút. App đang chạy không bị ảnh hưởng.

| Nguyên nhân | Cách sửa |
|---|---|
| Cài dependency không có lockfile, phải resolve lại cả cây | Commit lockfile (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `poetry.lock`…) |
| Chạy test, lint hoặc tải data lớn trong bước build | Chuyển test, lint sang CI |
| Lệnh trong Dockerfile chờ host chưa được mở tới hết giờ (log có `egress từ chối`) | Gửi tên host tới hello@embra.cloud |
| Dockerfile copy cả code trước khi cài dependency, sửa code là cài lại từ đầu | Copy file khai dependency và cài trước, copy code sau (mẫu dưới) |

```dockerfile
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
```

Mở **"Xem build logs"** để thấy build dừng ở bước nào, sửa rồi push lại.

**Data an toàn?** Có. Không deploy gì.

**Liên hệ khi:** build dừng ở bước tải package từ host đã mở, hoặc build dưới 25 phút trên máy bạn mà vẫn hết giờ trên Embra.

### `HEALTHCHECK_FAILED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 200 | Không | `fix_input` | `10` | Sửa theo mục này rồi làm lại |

<!-- /reason-meta -->

App mới chạy lên nhưng không trả lời health check đúng, nên Embra không chuyển traffic sang (hoặc đã trả traffic về bản cũ).

| Câu lỗi | App lúc này |
|---|---|
| `Bản mới không qua readiness trong thời gian khởi động. Bản cũ vẫn phục vụ.` | Bản cũ vẫn chạy. Deploy đầu thì chưa có bản nào chạy |
| `Bản mới lỗi sau khi nhận traffic, route đã được trả về bản cũ.` | Bản mới lỗi trong 30 giây theo dõi, traffic đã về bản cũ |
| `App không qua readiness sau khi chạy lại; app vẫn đang tạm dừng.` | Bạn bật lại app đang tạm dừng nhưng app không lên, app vẫn tắt |
| `App không chạy được trên bản khôi phục (không qua readiness). …` | Restore bị huỷ, app và database cũ vẫn chạy |
| `Deploy đã xong nhưng app chưa trả lời kiểm tra sức khoẻ sau 2 phút. …` (CLI) | `embra deploy` chờ 2 phút mà app chưa healthy. Xem app log |

Embra gọi `GET` tới `health_path` mỗi 2 giây, cần **3 lần 2xx liên tiếp** trong `startup_grace_seconds` (mặc định 60 giây). Chi tiết: [Health check](/huong-dan/chuan-bi-app/#health-check).

| Nguyên nhân | Cách sửa |
|---|---|
| App listen `127.0.0.1` hoặc `localhost`, ngoài container không gọi được | Listen `0.0.0.0` (mẫu theo framework bên dưới) |
| App listen port khác `[deploy] port` (mặc định 3000), ví dụ port mặc định của framework (8000, 8080, 5173) | Đọc port từ env var `PORT`. Embra đặt `PORT` bằng `[deploy] port`, trừ khi bạn tự đặt secret `PORT` |
| `health_path` trả 3xx: redirect sang trang login, sang HTTPS hoặc thêm `/`. Redirect không tính là đạt | Làm route riêng, ví dụ `/healthz`, trả 2xx, không login, không redirect |
| `health_path` trả 4xx: route không tồn tại, cần login, hoặc framework chặn header `Host` lạ. Embra gọi thẳng IP nội bộ của container, nên `Host` là `IP:cổng`, không phải domain của bạn | Như trên; với Django xem middleware mẫu bên dưới |
| App crash khi start: thiếu secret, không connect được database, chạy migration lúc start (user database của app không có quyền đổi schema) | Đọc app log. Bỏ lệnh migration lúc start (`prisma migrate deploy`, TypeORM `synchronize: true`…): migration đi qua Embra, xem [Database và migration](/huong-dan/database-va-migration/) |
| App start chậm hơn `startup_grace_seconds` | Tăng `startup_grace_seconds` (tối đa 300) |

**Cách sửa:**

1. Mở **"Logs"**, đọc app log quanh giờ deploy fail. Crash khi start hiện rõ ở đây.
2. Xem khối **"Nội dung từ app — không do Embra viết"**: response app trả ở lần health check cuối.
3. Sửa theo bảng trên, khai route health check trong `embra.toml`:

   ```toml
   [deploy]
   health_path = "/healthz"
   ```

4. Push lại.

<details>
<summary>Mẫu listen <code>0.0.0.0:$PORT</code> theo framework</summary>

**Express:**

```js
const port = Number(process.env.PORT) || 3000;
app.get('/healthz', (req, res) => res.send('ok'));
app.listen(port, '0.0.0.0');
```

**NestJS** (`src/main.ts`):

```ts
await app.listen(Number(process.env.PORT) || 3000, '0.0.0.0');
```

**Next.js** (`package.json`):

```json
{
  "scripts": {
    "start": "next start -H 0.0.0.0 -p ${PORT:-3000}"
  }
}
```

Dùng `output: 'standalone'` và chạy `node server.js` trong Dockerfile thì đặt thêm `HOSTNAME`:

```dockerfile
ENV HOSTNAME=0.0.0.0
CMD ["node", "server.js"]
```

**Django** (gunicorn, trong Dockerfile):

```dockerfile
CMD gunicorn myproject.wsgi --bind 0.0.0.0:${PORT:-3000}
```

Django trả 400 khi `Host` không có trong `ALLOWED_HOSTS`, và có thể redirect sang HTTPS nếu bật `SECURE_SSL_REDIRECT`. Cho health check một middleware riêng, đặt **đầu tiên** trong `MIDDLEWARE`:

```python
# myproject/health.py
from django.http import HttpResponse


class HealthCheckMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        if request.path == "/healthz":
            return HttpResponse("ok")
        return self.get_response(request)
```

```python
# settings.py
MIDDLEWARE = [
    "myproject.health.HealthCheckMiddleware",
    # ... các middleware còn lại
]
```

**Laravel** (trong Dockerfile):

```dockerfile
CMD php artisan serve --host=0.0.0.0 --port=${PORT:-3000}
```

</details>

:::caution[`$PORT` trong dạng mảng]
`CMD ["node", "server.js"]` và `start = ["node", "dist/main.js"]` trong `embra.toml` là dạng mảng, không qua shell, nên `$PORT` trong đó **không** được thay bằng giá trị. Đọc `PORT` trong code, hoặc bọc bằng shell: `CMD ["sh", "-c", "gunicorn myproject.wsgi --bind 0.0.0.0:$PORT"]`.
:::

**Data an toàn?** Tuỳ trường hợp:

- **Bản mới không qua health check:** chưa có traffic thật tới bản mới. Nhưng app mới đã chạy code start với `DATABASE_URL`, nên data code đó ghi (ví dụ seed lúc start) vẫn còn.
- **Bản mới lỗi sau khi nhận traffic:** bản mới đã phục vụ request thật lúc được theo dõi. Data ghi lúc đó vẫn còn trong database.
- **Mọi trường hợp:** plan có migration thì **migration đã chạy vẫn giữ nguyên**, bản cũ đang chạy trên schema mới. Đừng sửa file migration đã chạy để "hoàn tác", Embra sẽ báo [`MIGRATION_HISTORY_CHANGED`](#migration_history_changed). Muốn đổi lại schema thì thêm file migration mới.

**Retry?** Không, khi chưa sửa gì: health check chạy lại sẽ fail y như cũ.

**Liên hệ khi:** app chạy đúng `0.0.0.0:$PORT` và trả 2xx ở `health_path` khi chạy bằng Docker trên máy bạn, mà Embra vẫn báo lỗi.

### `REPO_CONFIG_INVALID`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 400 | Không | `fix_input` | `2` | Sửa theo mục này rồi làm lại |

<!-- /reason-meta -->

`embra.toml` có lỗi. Câu lỗi luôn bắt đầu bằng `embra.toml:` và nêu tên field sai. Phát hiện lúc build thì bạn thấy mã [`BUILD_FAILED`](#build_failed) với cùng câu.

| Câu lỗi (ví dụ) | Cách sửa |
|---|---|
| `embra.toml: field lạ deploy.prot.` | Sửa tên field (ở đây là `port`). Embra không bỏ qua field lạ |
| `embra.toml: field deploy.port sai kiểu giá trị.` | Sửa kiểu: `port = 3000`, không phải `port = "3000"` |
| `embra.toml: sai cú pháp TOML ở dòng 12.` | Sửa cú pháp ở đúng dòng đó (thiếu ngoặc kép, thiếu `]`…) |
| `embra.toml: build.builder phải là "railpack" hoặc "dockerfile".` | Sửa giá trị, hoặc bỏ dòng để Embra tự chọn |
| `embra.toml: deploy.startup_grace_seconds phải > 0.` | Đặt từ 5 tới 300 giây |
| `embra.toml: … phải là đường dẫn tương đối trong repo.`, `… không được trỏ ra ngoài repo.` | Path tính từ gốc repo (hoặc từ `root`), không bắt đầu bằng `/`, không dùng `..` ra ngoài |
| `embra.toml: build.env.EMBRA_…: tiền tố EMBRA_ dành riêng cho Embra.` | Đổi tên biến |
| `embra.toml: cron.<tên>.schedule: …` | Cron 5 field, giờ UTC, cách nhau ít nhất 5 phút |
| `embra.toml: file vượt 65536 byte.` | Rút gọn file, tối đa 64 KiB |

So với [tham chiếu `embra.toml`](/huong-dan/chuan-bi-app/#embratoml). Kiểm cú pháp trên máy, ví dụ `python3 -c "import tomllib; tomllib.load(open('embra.toml','rb'))"`, rồi commit và push lại.

**Data an toàn?** Có. Không deploy gì.

### `SOURCE_NOT_CONNECTED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 409 | Không | `fix_input` | `10` | Sửa theo mục này rồi làm lại |

<!-- /reason-meta -->

Embra không đọc được repo GitHub của environment này.

**Câu lỗi:**

- `Environment chưa nối với repo GitHub. …`
- `Environment không còn nối với repo GitHub.`
- `GitHub installation đã bị gỡ hoặc tạm dừng.`
- `Không lấy được quyền đọc repo: installation đã bị gỡ, tạm dừng hoặc mất quyền truy cập repo.`
- `Không đọc được nhánh đã nối: repo, nhánh hoặc installation không còn truy cập được.`
- `Hãy đăng nhập bằng GitHub trước khi kết nối repo.`

**Nguyên nhân hay gặp:**

- Embra GitHub App bị gỡ hoặc tạm dừng ở account hoặc organization.
- Lúc cài GitHub App bạn chọn "Only select repositories" và repo này không có (hoặc vừa bị bỏ ra).
- Repo bị đổi tên, chuyển owner hoặc bị xoá. Branch đã connect bị đổi tên hoặc xoá.
- Bạn login Embra bằng Google. Chỉ người login bằng GitHub mới connect được repo.

**Cách sửa:**

1. Mở **Cài đặt → "Source code"** → **"Cài / cập nhật quyền GitHub App"**.
2. Cấp lại quyền cho repo trên GitHub.
3. Kiểm tên repo và branch còn đúng. Branch đổi tên thì connect lại branch mới.
4. Bấm **"Build lại"**.

Xem thêm [Deploy từ GitHub](/huong-dan/deploy-tu-github/#tạo-app-lần-đầu).

**Data an toàn?** Có. App đang chạy vẫn chạy, chỉ không build được bản mới.

### `SECRET_REVOKED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 409 | Không | `fix_input` | `10` | Sửa theo mục này rồi làm lại |

<!-- /reason-meta -->

Một secret mà bản deploy cần đã bị thu hồi, hoặc chưa có version nào còn hiệu lực. Ví dụ: `Một secret của release đã bị thu hồi sau khi plan. Đặt version mới rồi plan lại.` hoặc `Secret <TÊN> chưa có version nào còn hiệu lực. …`

## Database và migration

Câu lỗi migration đôi khi ghi "lớp" của câu lệnh. Đối chiếu với [Embra kiểm migration thế nào](/huong-dan/database-va-migration/#embra-kiểm-migration-thế-nào):

| Lớp | Nhóm |
|---|---|
| A | An toàn |
| B | Đổi hoặc xoá data |
| C | Khoá bảng lâu |
| D | Không chạy trong transaction |
| E, F | Chưa hỗ trợ (E: Embra không parse được câu lệnh; F: bị cấm) |

### `MIGRATION_UNSUPPORTED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 422 | Không | `fix_input` | `10` | Bỏ câu lệnh lớp E/F, push lại |

<!-- /reason-meta -->

Một câu lệnh trong file migration thuộc loại Embra chưa chạy được, nên plan bị từ chối trước khi đụng database. Sau build thành công, console hiện **"Build xong · cần sửa config"** và **"Không tạo được plan deploy"**.

**Câu lỗi:**

- `File 0003_x.sql, câu lệnh #2 (CreateFunctionStmt) lớp E: …` hoặc `… lớp F: …`
- `File 0003_x.sql: không đọc được SQL nên không thể chứng minh an toàn.`
- `File 0004_x.sql, câu lệnh #1 (IndexStmt) lớp D: … lệnh không chạy trong transaction (như CREATE INDEX CONCURRENTLY) phải ở file riêng, chỉ có đúng một câu lệnh`
- `SQL của migration đã thay đổi bảng nội bộ của Embra. Đã rollback; không được phép.`
- `Migration không hợp lệ để chạy trên production.`

| Nguyên nhân | Cách sửa |
|---|---|
| File có function, procedure, trigger, view, khối `DO`, `CREATE EXTENSION`, `CREATE SCHEMA`, `GRANT`/`REVOKE` hoặc `COPY` (migration do ORM sinh hay có) | Chuyển logic đó vào code app. Embra chưa chạy được các câu này |
| File có `BEGIN`/`COMMIT` | Bỏ đi. Embra tự bọc mỗi file trong một transaction |
| `CREATE INDEX CONCURRENTLY` chung file với câu khác | Tách ra file riêng, chỉ có đúng câu đó |
| SQL viết cho database khác (MySQL, SQLite) hoặc cú pháp Postgres không parse được | Viết lại bằng SQL Postgres |

Tìm câu lệnh theo số `#` (tính từ 1) trong file mà câu lỗi nêu; câu gốc nằm trong khối **"Nội dung từ app — không do Embra viết"**. File này chưa từng chạy nên sửa thẳng được, rồi commit và push lại.

**Data an toàn?** Có. Embra từ chối từ bước lập plan. Riêng `SQL của migration đã thay đổi bảng nội bộ của Embra.` xảy ra lúc chạy, và Embra đã rollback câu lệnh đó.

### `MIGRATION_REHEARSAL_FAILED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| HTTP | Retry tự động | `next_action` | Exit code | Lệnh tiếp |
|---|---|---|---|---|
| 200 | Không | `fix_input` | `10` | Sửa SQL, kiểm bằng `embra plan` rồi push |

<!-- /reason-meta -->

Migration chạy lỗi:

| Câu lỗi | Lỗi ở đâu |
|---|---|
| `Diễn tập migration thất bại trên bản sao dữ liệu; chưa đụng production. …` | Trên bản sao data. Production chưa bị đụng |
| `Migration lỗi trên production dù đã diễn tập thành công: production khác bản sao. Câu lệnh lỗi đã rollback.` | Trên production. Câu lệnh lỗi đã rollback |

Lỗi Postgres (ví dụ `column "status" of relation "orders" contains null values`) nằm trong khối **"Nội dung từ app — không do Embra viết"**, kèm tên file và câu lệnh lỗi.

**Nguyên nhân hay gặp:**

- Thêm cột `NOT NULL` không có `DEFAULT` vào bảng đã có data.
- Tạo `UNIQUE` hoặc foreign key khi data hiện có vi phạm (trùng giá trị, tham chiếu dòng không tồn tại).
- Đổi kiểu cột mà data cũ không convert được (ví dụ chữ sang số).
- Tham chiếu bảng hoặc cột chưa có, do thứ tự file sai.
- Migration chạy được trên database rỗng ở máy bạn nhưng fail với data thật.

**Cách sửa:** sửa SQL cho chạy được với data hiện có. Ví dụ thêm cột bắt buộc theo ba bước:

```sql
ALTER TABLE orders ADD COLUMN status text;
UPDATE orders SET status = 'paid' WHERE status IS NULL;
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
```

Hoặc gọn hơn: `ALTER TABLE orders ADD COLUMN status text NOT NULL DEFAULT 'paid';`

File lỗi chưa được áp nên sửa thẳng được. **Đừng sửa file đã áp** ở các lần deploy trước. Commit và push lại, Embra diễn tập lại trước khi chạy.

**Data an toàn?** Lỗi lúc diễn tập: production không bị đụng. Lỗi trên production: câu lệnh lỗi đã rollback, code cũ vẫn chạy. Mỗi file chạy trong transaction riêng, nên plan nhiều file thì các file trước file lỗi có thể đã áp; Embra ghi nhận và lần sau chỉ chạy các file còn lại.

**Liên hệ khi:** lỗi trên production mà bạn không tìm ra production khác bản sao ở đâu.

### `DOMAIN_NOT_VERIFIED`

<!-- reason-meta: generated by scripts/reasons.mjs, do not edit -->

| Nguyên nhân | Cách sửa |
|---|---|
| DNS chưa propagate xong (thường 5–30 phút) | Đợi vài phút |
| Bật Cloudflare proxy (mây cam), Embra chỉ thấy IP Cloudflare | Chuyển record sang **DNS only** (mây xám) |

## Khi Embra dừng lại chờ kiểm tra

Ba mã dưới đây chung một nguyên tắc: khi **không chắc** một bước đã xong hay chưa, Embra **cố ý dừng** thay vì tự retry. Retry một việc chưa rõ kết quả, như chạy migration hai lần hay chuyển database khi chưa biết trạng thái, có thể làm hỏng data. Đội Embra xác minh trạng thái thật rồi mới mở lại environment.

|---|---|---|---|---|
| 200 | Không | `contact_operator` | `30` | Không có, cố ý. Email hello@embra.cloud kèm `operation_id` |

<!-- /reason-meta -->

Một thao tác trên environment (deploy, rollback, restore, bật/tắt app…) kết thúc mà Embra không xác định được kết quả, ví dụ mất kết nối với server giữa chừng. Console hiện **"Cần đội Embra hỗ trợ"**, trang Tổng quan hiện **"Đội Embra cần kiểm tra trước khi bạn deploy tiếp"**.

**Trạng thái lúc này:**

- Embra giữ nguyên traffic như lúc sự cố. Tuỳ thời điểm, app có thể đang chạy bình thường, đang chạy bản mới, hoặc đang dừng (ví dụ sự cố lúc chuyển sang bản restore).
- Environment bị chặn: deploy, build khi push, rollback, restore, bật/tắt app, đổi domain, nhập data đều bị từ chối với [`ENVIRONMENT_BLOCKED`](#environment_blocked).
- Cron không chạy. Backup định kỳ tạm dừng.

**KHÔNG nên:**

- **Xoá environment.** Vẫn xoá được, nhưng xoá luôn database và backup mà đội Embra cần để xác minh và khôi phục.
- Tự chạy SQL để "sửa" schema hoặc data: làm việc xác minh khó hơn.
- Push liên tục hoặc thu hồi secret để "gỡ chặn": không có tác dụng.

**Nên:**

1. Bấm **"Liên hệ hỗ trợ"** trên console, hoặc email hello@embra.cloud kèm mã operation, workspace, environment và giờ.
2. Ghi lại thao tác bạn vừa làm trước khi lỗi xuất hiện.
3. App đang lỗi với người dùng thì ghi rõ trong email để đội Embra ưu tiên.

- **Code cũ vẫn chạy.** App mới chưa start, vì Embra chỉ start app mới sau khi migration xong.
- Schema có thể là bản cũ hoặc mới. Mỗi file migration chạy trong transaction riêng, nên một file hoặc đã áp trọn vẹn, hoặc chưa áp gì (trừ file `CREATE INDEX CONCURRENTLY`, vốn không chạy trong transaction).
- Embra đã chụp snapshot database ngay trước khi chạy migration.
- Environment bị chặn như ở [`RECOVERY_REQUIRED`](#recovery_required).

**KHÔNG nên:**

- Xoá environment hoặc database.
- Sửa, đổi tên hay xoá file migration đang chờ, hoặc thêm migration mới để "chạy lại".
- Tự chạy lại câu lệnh migration bằng tay.

**Nên:** email hello@embra.cloud kèm mã operation, workspace, environment và giờ. Đội Embra kiểm tra schema thật, ghi nhận đúng kết quả rồi mở lại environment.

## Mã thoát của CLI

Dùng exit code để script CI biết nên làm gì:

| Exit code | Nghĩa |
|---|---|
| `0` | Xong |
| `1` | Lỗi login, không tìm thấy, không kết nối được (`API_UNREACHABLE`), hoặc lỗi phía Embra |
| `2` | Input sai (`INVALID_INPUT`, `REPO_CONFIG_INVALID`, `SOURCE_ARCHIVE_INVALID`) |
| `10` | Thao tác bị từ chối hoặc fail (phần lớn mã lỗi) |
| `20` | Đang chờ approve (`APPROVAL_REQUIRED`, `MIGRATION_DATA_LOSS`) |
| `30` | Cần đội Embra (`RECOVERY_REQUIRED`, `MIGRATION_UNKNOWN`, `ENVIRONMENT_BLOCKED`, tạm ngưng) |
| `75` | Tạm thời, thử lại sau (`RATE_LIMITED`, `TEMPORARILY_UNAVAILABLE`), hoặc hết thời gian chờ (`WAIT_TIMEOUT`) |
